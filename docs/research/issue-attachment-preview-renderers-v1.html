按类型渲染
  • Markdown：通过 /api/attachments/{id}/content 拉正文，用 iOS 现有 MarkdownText 渲染。
  • HTML：通过同一文本代理拉正文，用 WKWebView 非持久数据环境渲染。
  • XML/JSON/源码/text：按文本源码显示，第一版先保证可读、可复制、可横向滚动。
  • 下载/分享/外部打开继续保留，避免 preview 不支持时卡住用户。
核心判断：不要直接 fetch 或打开 downloadUrl 来渲染文本；按官方 Web 端方案走 authenticated content proxy。

现状差距

模块状态缺口
数据模型已具备Attachment 有 filename / contentType / downloadUrl / sizeBytes。
Issue UI半具备附件行现在是 Link(downloadUrl)，没有 App 内预览入口。
APIClient缺方法没有 getAttachmentContent Swift 方法。
Markdown可复用已有 MarkdownText，但复杂 GFM 能力弱于 Web。
HTML需隔离需要 WKWebView 安全策略和导航拦截。

官方 Web 端依据

分类器

packages/views/editor/utils/preview.ts 定义 PreviewKind：image、pdf、video、audio、markdown、html、text。

统一 Modal

attachment-preview-modal.tsx 统一处理媒体和文本；Markdown 复用 ReadonlyContent。

HTML 沙箱

html-preview-body.tsx 使用 iframe srcdoc + sandbox="allow-scripts"，不允许 same-origin。

服务端已有 GET /api/attachments/{id}/content，2 MB 上限，非文本 415，超大 413，返回 text/plain 防止浏览器误执行。

iOS 落点

  • AttachmentPreviewKind.swift：迁移 Web 分类规则。
  • APIClient.swift：新增 getAttachmentContent。
  • AttachmentPreviewView.swift：统一加载、错误、下载、渲染框架。
  • HTMLAttachmentPreview.swift：UIViewRepresentable 包装 WKWebView。
  • IssueDetailView.swift：附件行从下载链接改为 preview 入口。

安全策略

  • HTML 不注入 App token，不共享持久 cookie/localStorage。
  • WKWebsiteDataStore.nonPersistent()，baseURL: nil。
  • 拦截外链导航，确认后交给系统打开。
  • 沿用后端 2 MB cap，iOS 可用 sizeBytes 提前提示。
  • XML 默认源码查看，不按 HTML 执行。
